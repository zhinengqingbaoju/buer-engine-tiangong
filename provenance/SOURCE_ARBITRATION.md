# SOURCE ARBITRATION｜来源冲突与规则等级仲裁
版本：v01_20261008

规则类型：HARD RULE / PROJECT PRACTICE / HEURISTIC / EXAMPLE / EXPERIMENTAL。

优先级：
1 用户当前明确决定
2 宪法
3 当前有效项目事实/锁定资产
4 四份核心原文的对应专业规则
5 当前官方模型/平台真实能力 + Muse实测
6 HELL GRIND真实生产证据
7 成熟影视工业样板
8 历史系统/第三方经验

关键仲裁：
A-01｜7窗口覆盖旧9窗口：资产锁定→视觉资产+状态；测试→生成TEST MODE；修理工→QA开单、责任岗位修、QA复验。HARD RULE。
A-02｜HELL GRIND官方11阶段原件MISSING；当前流程必须标“不二引擎重建版”。HARD RULE。
A-03｜传统Shot List只借Scene/Shot/Size/Angle/Movement/Lens等结构；AI镜头追加首尾状态、版本、引用、风险、动作时间。PROJECT PRACTICE。
A-04｜Seedance官方/API能力与即梦/Muse UI分开；未实测UI标EXPERIMENTAL。HARD RULE。
A-05｜OpenAI API模型与ChatGPT/Muse图像入口分开。HARD RULE。
A-06｜MiniMax H3能力不得自动套给Hailuo 2.3；实际入口先识别型号。HARD RULE。
A-07｜不建立“绝对禁止negative prompt”；按目标模型官方与实测处理。HEURISTIC。
A-08｜Master Prompt内部字段与模型外层格式分离；Adapter只编译表达，不改事实。HARD RULE。
A-09｜单次随机失败→reroll候选；重复稳定失败→minimal rewrite；结构过载→redesign；表面缺陷→post。PROJECT PRACTICE/HEURISTIC，不写死次数阈值。
A-10｜generated / checked / candidate / adopted / locked严格分层。HARD RULE。
A-11｜聊天不是事实源；PROJECT_STATE + Registries为权威。HARD RULE。
A-12｜锁定/归档不等于压力测试通过。HARD RULE。
A-13｜Muse跨窗当前采用“总控写Task→用户目标Side Chat发执行待办→共享读写”。PROJECT PRACTICE，可随平台能力升级。
A-14｜Muse视频画面QA可用、音频内容理解FAIL；未外接STT/人工试听时audio=NOT_VERIFIED。HARD RULE（当前平台）。
A-15｜旧1+6 Production OS只作为历史/字段参考，不平行复活。HARD RULE。
A-16｜图片/关键帧/最终输出规格以 system/MEDIA_SPEC.md 的用户L0标准为准。HARD RULE。
A-17｜天工是系统名称，不是Muse额外运行Skill。四核心通过 CORE_BINDINGS 直接绑定岗位；Muse包不注册SKILL.md或agents/openai.yaml。HARD RULE（用户2026-10-08明确决定）。
A-18｜PROJECT_STATE.current_stage表示当前焦点对象阶段，不代表整个项目只能处在一个阶段。PROJECT PRACTICE。
A-19｜Asset采用状态统一为 planned/candidate/testing/adopted/locked/deprecated；不用approved与adopted双套同义词。HARD RULE（状态一致性）。

缺口处理：
缺官方原件→MISSING，不重建成“原文”。
只有社区说法→L5/EXPERIMENTAL。
当前官方文档有能力但Muse入口未测→模型能力ACTIVE，UI能力EXPERIMENTAL。
单次成功/失败→Case，不升级硬规则。
用户新决定→Decision approved并使旧决定superseded。
