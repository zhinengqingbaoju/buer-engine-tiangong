# PARALLEL_EXECUTION｜Muse并行执行规范
版本：v01_20261008

## 目的
7个固定窗口是长期专业岗位，不限制Muse临时并发能力。每个岗位/总指挥在没有硬依赖冲突时，应优先使用临时多Agent并行，提高调研、比较、审查、候选制作和批量检查效率。

## 原则
1. 大步骤按硬依赖串行；步骤内部可拆任务默认并行。
2. 临时Agent不是新增长期岗位，不维护私有项目真相。
3. 每路Agent使用同一输入快照、对象ID、版本与do_not_change。
4. 第一轮需要独立判断时，各路结论隔离；汇总后再交叉比较。
5. 结果只能由责任窗口/总指挥合并后写入Registry/State。
6. 任一Agent不得单独把candidate升级adopted/locked。
7. 涉及付费生成时仍受授权/额度限制；“可并行”不等于可擅自烧额度。
8. 依赖未稳定时不并行下游，避免大面积返工。
9. Muse可用Agent数量很多时，数量按任务可分性决定，不机械固定6路。
10. 最终21.32系统审查固定至少6路独立Agent；生产任务则按实际最优并发数。

## 适合并行
- 多来源研究/样板采集
- 多个独立资产候选
- 同一Prompt多次reroll（已授权时）
- 多模型A/B候选
- 独立QA维度/红队
- 多个无依赖镜头的文档准备
- 文件/版本/引用一致性核验

## 不适合并行
- 剧本决定尚未批准却提前做依赖镜头
- 资产版本未定却大规模生成下游
- GEO未定却并行设计互相依赖的反打
- 同一文件由多Agent无锁并发写入
- 需要用户单一创作裁决的问题
